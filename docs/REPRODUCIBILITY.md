# Reproducibility (Milestone 10)

The audit is generated by `python evaluation/build_final_report.py`, which reads the stored runs only. The output is `artifacts/final/reproducibility.json`.

## Classes
| Class | Meaning |
|---|---|
| **A** | Directly reproducible from existing artifacts |
| **B** | Reproducible by re-running an existing evaluation |
| **C** | Documented but not currently reproducible |
| **D** | Synthetic / demonstration only |

| Result | Class | How to reproduce | Stored artifacts |
|---|---|---|---|
| M3 Markov baselines (B0/B1/M1/M2) | **B** | `python scripts/fetch_attack.py`, `build_attack_kb.py`, `fetch_attack_flow.py`, `build_attack_flow_corpus.py`, `build_vocabulary.py`, then `python evaluation/run_markov_baseline.py` (recorded runtime 103 s) | metrics, predictions, B1/M1/M2 model JSON |
| M4 LSTM / hybrid / beam search | **B** | `python evaluation/run_sequence_models.py` (CPU, seeded; recorded runtime 518 s) | metrics, training history, predictions, 36 fold checkpoints |
| M5 CIC-IDS2017 detectors | **B** | Manual download of `GeneratedLabelledFlows.zip` (registration form), then `python scripts/register_cicids2017.py` and `python evaluation/run_classical_detection.py` (recorded runtime 193 s) | metrics, per-row test predictions, model artifacts |
| M6 quantum second opinion | **B** | `python evaluation/run_quantum_adjudicator.py` (recorded runtime 962 s; needs the M5 run and models) | metrics, band predictions, adjudicator artifacts |
| M7 integration demonstration | **D** | `python evaluation/run_integration_demo.py` (recorded runtime 1.4 s) | results, checks, END_TO_END SQLite record |
| M10 tables and figures | **A** (with the local stored runs) | `python evaluation/build_final_report.py` (reads the git-ignored `reports/runs/`; on a fresh clone, regenerate the runs first) | `artifacts/final/` (committed) |
| M10 end-to-end validation | **D** (synthetic input) | `python evaluation/validate_end_to_end.py`; opt-in dashboard ↔ live API test: `HQC_LIVE_API_URL=… npx vitest run src/test/live-api.test.tsx` against a server started with a scratch `HQC_DB_PATH` | `artifacts/final/e2e_validation.json` |

No result is class **C**. Re-running is not required for any reported number. Every stored run has its config, metrics and (where applicable) predictions on disk.

## Regenerating runs on a fresh clone
The stored runs (`reports/runs/`), models (`models/generated/`), downloaded data (`data/`) and SQLite databases are local and git-ignored. A fresh clone contains the code, configuration, tests and the final record in `artifacts/final/`, but none of the run folders. To reproduce:
1. Download and build the knowledge data, then (for M5/M6) register the manually downloaded CIC-IDS2017 archive. See the README and `models/README.md`.
2. Re-run the evaluations (class B). Each run gets a **new timestamped run ID**.
3. Update the run IDs pinned to the stored runs:

| File | Pins | Used by |
|---|---|---|
| `configs/integration.yaml` | `markov_run_id` (M3), `lstm_run_id` (M4), `classical_run_id` (M5), `quantum_run_id` (M6) | API services and the M7 integration demo (models load from `models/generated/<task>/<run-id>/`) |
| `configs/quantum_adjudicator.yaml` | `classical_run_id` (M5) | M6 (reads the M5 models and predictions) |
| `configs/sequence_prediction.yaml` | `reference_run` (M3) | M4 read-only comparison with M3 |
| `evaluation/build_final_report.py` | `RUN_M3` … `RUN_M7` | Regenerating `artifacts/final/` |

Until the M3/M4 runs and the knowledge base exist, the API's `/api/v1` intelligence endpoints return 503 (see `API.md`). The evaluation scripts stop with a one-line "missing prerequisite" message and exit code 2. They write no run folder, and `validate_end_to_end.py` leaves the stored `e2e_validation.json` untouched.

## Caveats
- **Uncommitted source code.** All five stored runs record git commit `c2813d4` with `working_tree_dirty: true`: the code that produced M3–M7 is the uncommitted working tree.
  - `artifacts/final/reproducibility.json` records a SHA-256 fingerprint of `backend/`, `configs/`, `evaluation/` and `scripts/` at report time (127 files).
  - For full source provenance, commit the tree and re-run the evaluations (class B), then compare against the stored metrics.
- **Repository cleanup after the report.** After `artifacts/final/` was generated:
  - The unused `ingestion/` and `preprocessing/` placeholder packages were removed.
  - A missing-data check was added (`backend/hqc/evaluation/prerequisites.py`), and the M3/M4 scripts and `validate_end_to_end.py` now use it.
  - The success path is unchanged: the corpus checksum is still verified and recorded. But the source fingerprint in `reproducibility.json` no longer matches the current tree. Nothing was re-run and no stored result changed.
- **Code changed after the M6 run.** One change after the M6 run is numerically equivalent on its data: the CV balanced-accuracy helper was rewritten to avoid a warning, and is identical whenever both classes are present, which is always the case in the real CV pools. It is covered by a unit test.
- **The CIC-IDS2017 download cannot be scripted.** It requires the UNB registration form. Integrity is guaranteed by the recorded SHA-256 values.
- **Wall-clock times vary** with hardware: Apple M4, 10 cores.
